MISSION BRIEF
העיר כבתה. הקוד בידיים שלכם.
כל תא הוא בלוק בעיר. כדי להחזיר את האור צריך להבין אילו תאים הקוד יבחר. המטריצה כאן היא מערך דו־ממדי בתכנות, ולא תרגול כפל מטריצות.
  1. ניבוי: קוראים את הקוד ומסמנים את כל התאים שעבורם התנאי נכון.
  2. תיקון: התאים המסומנים במסגרת כחולה הם היעד. מתקנים את התנאי כדי לבחור בדיוק אותם.
  3. אנרגיה: כל תא מכיל מספר. מנבאים את סכום הערכים שהקוד יאסוף.
  4. יצירה: מציירים תבנית, כותבים תנאי ומשווים. הורידו את הקוד והריצו אותו בסביבת הפיתוח.
האינדקס הראשון הוא row (שורה), השני הוא col (עמודה). שניהם מתחילים ב־0. לחצו על תא או עברו עם Tab ו־Enter/רווח; חיצי המקלדת מזיזים את המיקוד ברשת.
כל משימה מעניקה עד 3 כוכבים: פתרון ראשון ללא עזרה = 3; אחרי ניסיון נוסף או רמז = 2; אחרי חשיפת מעקב = 1. תמיד אפשר לשפר. אין הגבלת ניסיונות.

בדיקת הבנה עצמאית
במערך 4×6: (1) כתבו תנאי למסגרת; (2) כמה תאים מקיימים row == col? (3) הסבירו מדוע col < rows אינו גבול נכון לסריקת העמודות. תשובות: row == 0 || row == rows - 1 || col == 0 || col == cols - 1; ארבעה תאים; מספר העמודות הוא cols, לא rows.
בדקו גם הסבר מילולי והעברה לגודל חדש. דוח ההתקדמות כולל כוכבים, ניסיונות ועזרה, ללא שמות. ההתקדמות נשמרת מקומית בלבד. אפשר לפתוח את קובץ ה־HTML בלי אינטרנט; רק קישורי המחקר דורשים חיבור.
על הקוד
C# משתמש במערך מלבני int[,] וב־GetLength; Java משתמש ב־int[][] ובאורך של כל שורה. המשחק יוצר מערכים מלבניים. ביטויים נתמכים בלבד, ללא קוד חופשי או קריאות לפונקציות. value הוא קיצור לערך בתא הנוכחי; בקוד שמורידים מופיעה גישת המערך המתאימה. קובץ הקוד כולל את הנתונים ואת Main/main ומדפיס את התאים ואת הסכום.
